# Agents Feature Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Agents feature per `docs/superpowers/specs/2026-08-10-agents-design.md`: a CE `agent` entity that generates a hidden multi-trigger workflow (branch_in → aiAgent/streamChat → branch_out) in a `__AI_AGENT__<uuid>` system project, with explicit publish, an Agents page, and an Agent Deployments page.

**Architecture:** Three phases. **A — platform groundwork**: the reserved `__triggerName` job-input discriminator, reserved-input-name validation, `SystemProjects` consolidation. **B — server domain**: `automation-agent` module group (api/service/graphql), channel registry, deterministic workflow generator, facade with provisioning/publish. **C — client**: Agents list/detail pages, draft test chat, Agent Deployments page reusing `ProjectDeploymentDialog`.

**Tech Stack:** Java 25 / Spring Boot 4, Spring Data JDBC, Liquibase, GraphQL (`extend type Query/Mutation` + `@QueryMapping` controllers), React 19 + TypeScript + react-query + GraphQL codegen, Vitest, JUnit 5 + Testcontainers.

    public static final String TRIGGER_NAME_INPUT = "__triggerName";

    private JobInputConstants() {
    }
}

**Generation rules (all from spec §Workflow generation):**
- Model on `KnowledgeBaseSourceWorkflowGenerator` (same module family, same Jackson usage): build a `LinkedHashMap` tree, serialize with the same ObjectMapper conventions. LinkedHashMap + position-sorted inputs ⇒ determinism.
- Trigger node names: `<channelType>_<n>` where n counts per channelType in position order (`chat_1`, `workflowCall_1`, `schedule_1`, `slack_1`…). Chat first, workflowCall second, then by `position`.
- workflowCall trigger parameters: `inputSchema` = the predefined JSON schema `{"type":"object","properties":{"message":{"type":"string"},"conversationId":{"type":"string"}},"required":["message"]}` serialized as a string (match how the trigger's `INPUT_SCHEMA` property is consumed — read `WorkflowNewWorkflowCallTrigger` + `WorkflowResponseUtils.triggerOutput`).
