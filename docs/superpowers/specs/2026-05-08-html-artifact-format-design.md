# HTML Artifact Format — Design

**Status**: Proposed
**Date**: 2026-05-08
**Owner**: Ivica Cardic
**Scope**: AI Hub (EE) — automation-ai-hub + platform-ai-hub

## 1. Context

The command center already supports agent-authored artifacts in eight formats: `MARKDOWN`, `CODE`, `CSV`, `JSON`, `DOCX`, `PPTX`, `CHART`, `IMAGE`. Each is a row in `asset_file` with an `AUTHORED` join to the parent `ai_hub_task`, generated by a format-specific `ArtifactGenerator` and dispatched through the single `generateArtifact` LLM tool.

What's missing is a way for the agent to author **interactive** artifacts — small self-contained HTML+JS apps the user can run inside ByteChef (a countdown clock, a map widget, a chess board, a custom interactive viewer). Today the LLM has to pick between `CODE` (renders as Monaco source, not as a live page) and `MARKDOWN` (no interactivity). Neither lets the user actually run the thing.

This spec adds an `HTML` format that:

- Persists the same way every other artifact persists (`asset_file` row, `AUTHORED` join).
- Is generated through the same `generateArtifact` tool with `format: "HTML"`.
- Is rendered in the existing resource panel, in a sandboxed iframe with scripts allowed but no same-origin access and no network egress.
- Has an in-app maximize toggle so a Tamagotchi-shaped artifact gets enough screen real estate without the user fighting a narrow side panel.

## 2. Scope

**In scope:**

- New `AssetFileFormat.HTML` enum value (append-only; ordinal pinned).
- New `HtmlArtifactGenerator` with strict validation and server-side CSP injection.
- Extend `GenerateArtifactToolCallback` — schema gains `HTML`, description gains a one-line steering rule on when to choose HTML vs CHART/MARKDOWN/etc.
- New `AiHubHtmlInteractivePane.tsx` viewer pane with iframe + maximize toggle, dispatched from `AiHubFileViewer.tsx` when `format === 'HTML'`.

**Explicitly out of scope (deferred to follow-on specs):**

- Content versioning — keeping a history of prior bytes when the agent rewrites an artifact. Needs an `asset_file_version` table, a viewer history pane, and a storage-of-prior-bytes question. Worth its own spec.
- Public shareable links — anonymous, revocable URLs. Needs share-token column, anonymous endpoint, rate limiting, abuse review of "ByteChef domain serves arbitrary sandboxed HTML to anonymous users." Worth its own spec.
- Browser-native Fullscreen API (`iframe.requestFullscreen()`). The `allow-fullscreen` sandbox flag is a separate relaxation; iOS Safari is partially broken on this; in-app maximize gets us the same perceived benefit at near-zero risk. Add later if a real ask shows up.
- Inline-in-chat rendering. The user opens HTML artifacts from the chat chip into the resource panel — same flow as every other artifact. Inline iframes in the message stream have their own height-management and weight problems; out of scope for v1.
- A separate `DASHBOARD` format. Dashboards are a composition of charts + text + layout, which is exactly what HTML covers. Adding `DASHBOARD` as its own format would be premature abstraction before we know what shape a structured dashboard spec should take.
- Agent cloning, background-running agents, and per-agent tool ACLs. These are separate features mentioned in the same competitor announcement (Gumloop v9.2.0) but they don't intersect with the artifact pipeline; they each need their own spec.

## 3. Architecture

Three layers, each touching exactly one extension point in the existing pipeline.

### 3.1 Persistence

Append `HTML` to `AssetFileFormat`:

```java
public enum AssetFileFormat {
    MARKDOWN, CODE, CSV, JSON, DOCX, PPTX, CHART, IMAGE,
    HTML  // NEW — append-only per the enum contract
}
```

`AssetFileFormatOrdinalStabilityTest` gets the new ordinal pinned. No new tables, no new columns. The artifact is a normal `asset_file` row with `mime_type = "text/html"`, `format = HTML`, `source = AI_GENERATED`, `generated_by_agent_source` and `generated_from_prompt` set per the existing convention. Authorship is recorded via the existing `(taskId, assetFileId, AUTHORED)` join through `AiHubTaskAssetFileService.recordAuthorship`.

The mime/format split matters here: the *mime* is the wire encoding (`text/html`); the *format* is the logical role discriminator that the viewer routes on. A user-uploaded HTML file (drag-and-drop) is `mime=text/html, format=null` and continues to render via the generic mime-only path with `sandbox=""` (no scripts). An AI-generated HTML artifact is `mime=text/html, format=HTML` and gets the trusted-generation render path with `sandbox="allow-scripts"`. Trust is conferred by the format column, not by the mime type.

### 3.2 Generation

New `HtmlArtifactGenerator extends AbstractTextArtifactGenerator`, registered with the existing `ArtifactGeneratorRegistry` for `format() = AssetFileFormat.HTML`. Two responsibilities:

1. **Strict validation** (see §4 below). Rejects malformed input synchronously with a multi-violation error message the LLM can fix on the next turn — same error shape as the JSON/CSV/CHART validators already use.
2. **Server-side CSP injection** (see §5 below). The generator parses the input, locates `<head>`, and inserts the CSP `<meta>` tag as the head's first child. If the input already has a CSP meta, ours is inserted *before* it (browsers honor the most restrictive of stacked CSPs). The LLM cannot defeat the CSP by writing its own, because ours is always evaluated alongside.

The generator runs synchronously inside the agent's tool-call dispatch, exactly like the existing text generators. No new streaming protocol.

### 3.3 Rendering

New React component `AiHubHtmlInteractivePane.tsx`:

- iframe with `sandbox="allow-scripts"` and `srcDoc={content}`.
- Toolbar with one button: a `MaximizeIcon`/`MinimizeIcon` toggle.
- Maximize state is local React state, not persisted — resets when the viewer closes or the user switches files.
- Maximized: a `position: fixed; inset: 0; z-index: 50` overlay covering the chat workspace area (not the browser chrome). Esc handler restores. Focus stays in the iframe (the iframe is the focus trap by default — sandbox prevents it from escaping anyway).
- Editor mode and split mode keep working: maximize is orthogonal, applied on top of whichever `viewMode` the user picked.

`AiHubFileViewer.tsx` dispatch order changes minimally:

```
if (format === 'CHART') → AiHubChartPane
if (format === 'HTML')  → AiHubHtmlInteractivePane   // NEW
if (image mime)         → PreviewPane
if (PPTX mime)          → PreviewPane (download fallback)
if (mime === 'text/html') → existing user-uploaded HTML path (sandbox="")  // UNCHANGED
... existing fallbacks ...
```

The new branch is checked before the generic `text/html` mime branch, so format-discriminated trust always wins.

## 4. Validator rules (strict)

Reject the artifact at generation time if any of these fail. The validator returns *all* violations in the error message, not just the first — so the LLM can fix the whole batch on the next turn instead of round-tripping per violation.

Parse with Jsoup (already on the classpath via the markdown stack). Then check:

1. **Document structure**: must contain `<!doctype html>` (case-insensitive), `<html>`, `<head>`, `<body>`. Fragments are not accepted because the CSP meta tag has to be injected as a child of `<head>` — no `<head>`, nowhere to put the policy.
2. **No external scripts**: every `<script>` element is either inline (no `src` attribute) or has a `src` whose scheme is `data:`.
3. **No external stylesheets**: every `<link rel="stylesheet">` has an `href` whose scheme is `data:`. Inline `<style>` is fine. Other `<link rel="…">` (e.g., `preconnect`, `prefetch`, `dns-prefetch`) is rejected — they exist only to talk to external hosts.
4. **No external media**: `<img>`, `<source>`, `<video>`, `<audio>`, `<track>` — every `src`, `srcset`, `poster` attribute is `data:` or empty. (`<picture>` follows from `<source>`.)
5. **No nested browsing contexts**: `<iframe>`, `<frame>`, `<frameset>`, `<embed>`, `<object>`, `<applet>` are all rejected. Allowing the artifact to open a nested browsing context defeats the sandbox boundary we're investing in.
6. **No external form actions**: `<form>` with an `action` attribute pointing at an absolute URL is rejected. Forms with no action or a relative action are accepted (the `allow-forms` sandbox flag is off so they no-op anyway, but explicit reject is clearer).
7. **No `<base>`**: `<base href="…">` is rejected — it would let scripts resolve relative URLs against an attacker-controlled origin.
8. **Size cap**: total content ≤ 1 MB after CSP injection.

The "no external refs" rules are the second layer of defense behind the CSP `connect-src 'none'` directive. CSP catches the request at runtime; the validator catches it at generation time so the agent gets a clear "rewrite this without the CDN script" signal instead of a silent runtime block.

If the LLM legitimately needs a library (e.g., a 3D widget that wants `three.js`), it inlines it as a `data:application/javascript;base64,…` URI. This is honest about the dependency — the bytes live in the artifact and show up in Monaco — and still passes validation.

Inline event handlers (`onclick="…"`, `onload="…"`) are *allowed*. CSP `script-src 'unsafe-inline'` is needed for the inlined `<script>` blocks the agent will write, and inline handlers travel under the same directive. This is a deliberate trade-off — disallowing inline handlers would force the LLM to attach listeners via `addEventListener` in a `<script>` block, which is more code and a strictly cosmetic improvement given that all script execution is already trusted within the sandbox.

## 5. CSP injection

The generator inserts this `<meta>` tag as the first child of `<head>`:

```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'none';
               script-src 'unsafe-inline' data:;
               style-src 'unsafe-inline' data:;
               img-src data:;
               font-src data:;
               media-src data:;
               connect-src 'none';
               base-uri 'none';
               frame-ancestors 'none';">
```

Per directive:

- `default-src 'none'` — every fetch type defaults to blocked unless explicitly allowed below.
- `script-src 'unsafe-inline' data:` — inline `<script>` blocks and inline event handlers run, plus `<script src="data:application/javascript;...">` is allowed so the LLM can inline a library (e.g. three.js for a 3D widget) as a data URI. No external script sources are allowed (no `https:`, no `'self'`, no specific hosts). The validator's "no external script srcs" rule is the second layer here — `data:` script srcs are explicitly permitted in §4 to make the inlined-library path work.
- `style-src 'unsafe-inline' data:` — inline `<style>` blocks and inline `style="…"` attributes work; `data:` URIs in `<link rel="stylesheet">` work; nothing else.
- `img-src data:`, `font-src data:`, `media-src data:` — only data-URI assets render. The validator already ensured no external `src` attrs exist; CSP makes that a hard runtime block.
- `connect-src 'none'` — the load-bearing directive. Blocks `fetch()`, `XMLHttpRequest`, `WebSocket`, `EventSource`, and `Navigator.sendBeacon`. The artifact cannot phone home regardless of what the script tries to do.
- `base-uri 'none'` — blocks `<base>` tags from being injected via DOM manipulation at runtime.
- `frame-ancestors 'none'` — prevents the artifact from being re-embedded in another page if a share link ever ships in a future spec.

If a future asset already has a CSP meta tag, ours goes first. Browsers evaluate stacked CSPs as the *intersection* of all policies — so the LLM cannot author a more permissive CSP to override ours.

## 6. Tool input

`GenerateArtifactToolCallback`'s schema gets `HTML` added to the `format` enum. The tool description gains one new sentence at the end:

> Use CHART for data visualization. Use HTML only for interactive apps that cannot be expressed as a chart, table, or markdown report (e.g. a countdown clock, a small game, a custom interactive widget).

The schema otherwise stays unchanged: `format`, `filename`, `content`, optional `metadataJson`. The steering line goes in the tool description (LLM-visible per turn, scoped to the format-choice decision) rather than in the agent system prompt — system prompt is the wrong layer for tool-input nudges.

## 7. Filename handling

`HtmlArtifactGenerator` auto-appends `.html` if the supplied filename lacks an extension or has a different one. This matches the existing `PptxArtifactGenerator` behaviour and saves the LLM a token-budget round trip when it forgets the extension.

## 8. Telemetry

Extend the existing per-format counter with the new tag value:

- `bytechef_artifact_generated{format=HTML}` — incremented on every successful HTML artifact persistence.
- `bytechef_artifact_generation_rejected{format=HTML, reason=<rule-name>}` — incremented on each validation failure, tagged with the rule that fired (`document_structure`, `external_script`, `external_stylesheet`, `external_media`, `nested_browsing_context`, `external_form_action`, `base_tag`, `size_cap`). Lets ops see which rules the LLM is hitting most so we know where to invest in better steering.

If the metric counters don't already exist on the other generators, they're added in this spec — small carry-along.

## 9. Tests

Server-side:

- `HtmlArtifactGeneratorTest` — happy path; each validation rule fails with a useful message; multi-violation errors return the full list, not just the first; CSP injection happens before any existing CSP tag; 1 MB size cap is enforced after CSP injection (not before).
- `AssetFileFormatOrdinalStabilityTest` — pin the new ordinal at position 8.
- `GenerateArtifactToolCallbackTest` — extend with HTML case: route hits the registry, output shape is correct, schema enum advertises `HTML`.
- `EnumOrdinalStabilityTest` — no change (HTML is on `AssetFileFormat`, not on a ai-hub enum).

Client-side:

- `AiHubHtmlInteractivePane.test.tsx` — iframe receives content via `srcDoc`; sandbox attribute is exactly `"allow-scripts"`; maximize toggle adds the fixed-overlay class; Esc collapses; component unmounts cleanly.
- `AiHubFileViewer.test.tsx` — dispatch routes `format === 'HTML'` to the new pane and *not* to the generic `text/html` branch; routing is order-independent of mime type.

## 10. Risks and defenses

- **Sandbox escape via same-origin grant**: explicitly avoided. `allow-same-origin` is *not* in the sandbox attribute. The iframe is treated as a unique opaque origin, cannot read parent cookies/localStorage, cannot hit ByteChef APIs as the user.
- **Data exfiltration via DNS/CSS/image side channels**: blocked by `connect-src 'none'` *and* the validator's "no external refs" rules. CSS `@import`, image side-channels, font side-channels — all gated by `data:`-only directives.
- **LLM authoring a malicious artifact intentionally**: the artifact runs in an iframe with no network egress, no parent access, no top-navigation, no form submission. The blast radius is the user's own session viewing the artifact — the artifact can show whatever it wants in its own iframe but cannot reach ByteChef state or the user's other tabs.
- **Stored XSS via the artifact content displaying in the chat thread without iframe isolation**: the chat surface renders artifacts as chips (filename + format), never as raw HTML. The HTML body only ever reaches the DOM via the iframe's `srcDoc`. Markdown rendering in chat uses react-markdown's default config (no `rehype-raw`, no `allowDangerousHtml`) which escapes any embedded HTML to text — so the artifact body cannot escape into the chat DOM through that path either.
- **Validator bypass via Jsoup parser quirks**: Jsoup is permissive by design (it parses bad HTML into best-guess trees). The validator should walk the parsed tree, not regex the input — and reject any element it doesn't understand. We accept that an attacker-flavoured input might parse into something Jsoup names oddly; the CSP and sandbox are the runtime backstops.
- **Resource exhaustion via giant inlined data URIs**: the 1 MB content cap is the gate. A 1 MB `data:image/png;base64,…` is a ~700 KB image — fine. A 10 MB inlined model is rejected; the LLM sees the size violation and either trims or splits.

## 12. Edge cases

- **First-turn race** (`taskId` not yet resolved): same as every other generator. The file persists, `taskLinked=false` flows back through the tool result, the agent surfaces a "this isn't joined to the conversation; attach manually if you want" hint to the user. No special handling.
- **Existing `text/html` mime path** (user drags an HTML file into the file picker): untouched. Continues to render with `sandbox=""` (no scripts). Trust is conferred by the `format` column, not the mime type — and a manually-uploaded HTML file does not get `format = HTML`.
- **Editor mode for HTML artifacts**: Monaco already has the `html` language; the existing `EditorPane` handles it via `languageForMimeType`. No change needed.
- **CE without EE**: `HtmlArtifactGenerator` is `@Component @ConditionalOnProperty(prefix = "bytechef.ai.ai-hub", name = "enabled", havingValue = "true")` — same gate as the other ai-hub artifact generators. CE without ai-hub enabled simply does not register the bean; an `HTML` tool call returns "no generator for format HTML" through the registry's existing path, which the LLM surfaces as a tool error. Behaviour is identical to how a CE deployment misses out on `DOCX`/`PPTX` generators today.
- **Liquibase**: no migration required. Append-only enum stored as ordinal in an existing column.

## 13. Implementation sequence

A suggested build order, smallest-blast-radius first:

1. Append `HTML` to `AssetFileFormat`; pin the ordinal in `AssetFileFormatOrdinalStabilityTest`.
2. Build `HtmlArtifactGenerator` with strict validation + CSP injection. Cover with unit tests (each rule + happy path + multi-violation message).
3. Wire the generator into `GenerateArtifactToolCallback` — schema enum and description update; extend the existing tool test.
4. Add `AiHubHtmlInteractivePane.tsx` with iframe + maximize toggle. Unit-test in isolation.
5. Wire dispatch in `AiHubFileViewer.tsx`; extend the viewer test.
6. End-to-end check: agent prompt → tool call with `format: HTML` → asset_file row → resource panel renders → maximize toggles.
