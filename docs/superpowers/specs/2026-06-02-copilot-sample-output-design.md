# Copilot: AI-Generated Sample Output — Design

- **Date:** 2026-06-02
- **Status:** Approved (design)
- **Edition:** EE only
- **Author:** Ivica Cardic
- **Issue:** [#2202](https://github.com/bytechefhq/bytechef/issues/2202) (output schema's sample output generated by AI)

## Context

A Workflow Developer wants to define an output schema quickly by describing the desired output in
natural language. ByteChef already turns a **sample output instance** (concrete example JSON) into a
schema deterministically, in two places. #2202 adds the AI step *before* that inference: prompt →
sample JSON instance → (existing) schema inference.

This is the fourth Copilot-in-place feature and reuses the now-established pattern (gating, IDOR
guard, `ChatModel`, fence-cleaning + parse-validate + one repair) from:

- `2026-06-02-property-copilot-design.md` — `generatePropertyValue` (TEXT/FORMULA).
- `2026-06-02-copilot-workflow-description-and-json-schema-design.md` — `JSON_SCHEMA` mode
  (#2109: generates a *schema*) and `generateWorkflowDescription` (#2503).

**#2202 is distinct from #2109.** #2109 generates a JSON *schema* directly. #2202 generates a sample
*instance* (example payload), which is more useful: the existing deterministic inference turns it
into a schema, and the payload itself is usable as the node's sample output for datapills/testing.

### Existing infrastructure this builds on (verified on the working branch)

- **Schema-builder sample dialog** —
  `client/src/pages/platform/workflow-editor/components/properties/components/property-json-schema-builder/PropertyJsonSchemaBuilderSampleDataDialog.tsx`:
  a Monaco editor bound to `curSchema` state; the footer "Generate" button POSTs the pasted JSON to
  `POST /api/platform/internal/generate-schema` (`SchemaGenerator.generateSchemaFromJson`) and calls
  `onChange(schema)`. It does **not** currently receive `workflowId`/`environmentId`.
- **Output-tab sample dialog** —
  `client/src/pages/platform/workflow-editor/components/node-details-tabs/output-tab/OutputTabSampleDataDialog.tsx`:
  a Monaco editor bound to `rawValue`/`parsedValue`; the footer "Upload" button calls
  `onUpload(json)`. Its parent (`OutputTab` / `OutputSchemaDisplay`) holds `workflowId`,
  `currentNode.name`, and `currentEnvironmentId`, and the upload path
  (`uploadWorkflowNodeSampleOutput`) infers + stores the node output schema server-side via
  `SchemaUtils.getOutputSchema`.
- **#2109 already threaded** `workflowId`/`workflowNodeName`/`environmentId`/`propertyPath` into
  `PropertyJsonSchemaBuilderSheet`; this design extends that chain one level into the sample dialog.
- **Property Copilot backend pattern** (ai-copilot modules): `@Service @ConditionalOnEEVersion
  @ConditionalOnProperty(bytechef.ai.copilot.enabled=true)` generators; GraphQL controllers
  `@ConditionalOnEEVersion @ConditionalOnCoordinator` with `Optional<generator>` and the
  `WORKFLOW_VIEW` IDOR guard (resolve projectId from client-supplied `workflowId`); `clean()` =
  `replaceAll("```[a-zA-Z]*", "").strip()`; JSON parse-validate with one repair retry; metric
  counter via `ObjectProvider<MeterRegistry>`.
- **Client gating mirror:** `ai.copilot.enabled` (from `useApplicationInfoStore`) + `ff-1570` (from
  `useFeatureFlagsStore`), exactly as `JsonSchemaCopilotBar` / `CopilotGenerateDescriptionButton`.

## Goal

On the node output-tab sample-data dialog, the user types a natural-language description of the
desired output, the AI generates a matching sample JSON instance that fills the dialog's editor for
review, and the user clicks the dialog's existing **Upload** button to run the existing
(deterministic) output-schema inference.

EE-only, single-shot, gated on `ai.copilot.enabled && ff-1570`.

## Non-goals (deferred)

- Multi-turn refinement / streaming.
- Grounding the sample on the node's component/action definition (free-form prompt only for v1).
- Auto-running the existing Generate/Upload after AI fills the editor (the user reviews and submits
  — keeps them in control, matches the existing review-then-submit flow, and is consistent with the
  replace-with-confirm choice).
- New deterministic schema-inference logic (reuse `/generate-schema` and the sample-upload path).
- A new feature flag (reuse `ff-1570`).

## Backend (new, in the `ai-copilot` modules)

1. **`ai-copilot-api`** (package `com.bytechef.ee.ai.copilot.sampleoutput`):
   - `SampleOutputCopilotRequest(String workflowId, String prompt, long environmentId)`.
     (`workflowId` is required for the IDOR guard; `workflowNodeName` is not needed — generation is
     prompt-only and not node-grounded for v1.)
   - `SampleOutputCopilotResult(String value, boolean valid, String message)`.
   - `SampleOutputCopilotGenerator` interface.
2. **`ai-copilot-service`** (package `...sampleoutput`):
   - `SampleOutputPromptBuilder.build(prompt)`: instructs the model to return ONLY a single realistic
     JSON instance (object or array) matching the user's description — example data, NOT a schema —
     no prose, no markdown, no code fences.
   - `SampleOutputCopilotGeneratorImpl` (`@Service @ConditionalOnEEVersion
     @ConditionalOnProperty(bytechef.ai.copilot.enabled=true)`): build prompt → `ChatModel` call →
     `clean()` → validate the result parses as a JSON **object or array** (via the project JSON
     util) → on failure one repair retry ("The previous attempt was not valid JSON. Return ONLY a
     valid JSON object or array.") → `valid=false`+message if still unparseable. Records
     `bytechef_sample_output_copilot_generate` with `outcome=success|invalid_json`.
3. **`ai-copilot-graphql`**:
   - `sample-output-copilot.graphqls`:
     ```graphql
     extend type Mutation {
         generateSampleOutput(input: GenerateSampleOutputInput!): GenerateSampleOutputPayload!
     }
     input GenerateSampleOutputInput {
         workflowId: ID!
         prompt: String!
         environmentId: Int!
     }
     type GenerateSampleOutputPayload {
         value: String!
         valid: Boolean!
         message: String
     }
     ```
   - `SampleOutputCopilotGraphQlController` (`@Controller @ConditionalOnEEVersion
     @ConditionalOnCoordinator`): IDOR guard identical to `PropertyCopilotGraphQlController`
     (resolve projectId from `workflowId`, require `WORKFLOW_VIEW`); `Optional<generator>` →
     `IllegalStateException` when copilot disabled.

The mutation is fully independent of `generatePropertyValue` / `generateWorkflowDescription`
(separate schema file, separate generator, separate package).

## Frontend

1. **GraphQL op** `client/src/graphql/platform/copilot/generateSampleOutput.graphql` + regenerate
   types → `useGenerateSampleOutputMutation`. Thin hook `useGenerateSampleOutput` returning
   `{generate, isPending}` where `generate(input)` → `data.generateSampleOutput` (`{value, valid,
   message}`).
2. **`SampleOutputCopilotBar`** (new, surface-agnostic; placed under
   `client/src/shared/components/copilot/`): a prompt textarea + Generate button, gated on
   `ai.copilot.enabled && ff-1570 && workflowId` (renders null otherwise). Props
   `{currentEditorIsEmpty, environmentId, onApply, workflowId}`. On generate: call the hook with
   `mode`-free input; if `!result.valid` show `result.message`; else if `!currentEditorIsEmpty`
   `window.confirm('Replace the current sample data?')` before `onApply(result.value)`. It knows
   nothing about schema vs output-upload — it only yields the JSON string.
3. **Wire into `OutputTabSampleDataDialog`** (the one live surface): add optional `environmentId`/
   `workflowId` props (passed by `OutputTab`, which holds `workflowId` + `currentNode` and reads
   `currentEnvironmentId` from `useEnvironmentStore`); render the bar above the editor; `onApply(value)`
   → `setRawValue(value)` + `setParsedValue(JSON.parse(value))`. `currentEditorIsEmpty =
   rawValue.trim().length === 0`. The existing footer **Upload** button then runs the deterministic
   `SchemaUtils.getOutputSchema` inference unchanged.

> **Discovered constraint (scope cut, documented honestly):** the other sample dialog,
> `PropertyJsonSchemaBuilderSampleDataDialog`, is currently **dead code** — no component renders it
> (verified: only its own file references it). Wiring the AI bar there would ship a feature no user
> can reach, so it is **excluded** from this work. The `SampleOutputCopilotBar` is built
> surface-agnostic, so if that dialog is ever made live it can drop the bar in with no backend
> change.

## Cross-cutting

- **Feature flag:** reuse `ff-1570` + `ai.copilot.enabled`.
- **Conventions:** EE license header + `@version ee` on all new `server/ee` files (incl. tests).
  Client: `sort-keys`, `…PropsI`/`…Props`, sorted destructured imports, Lucide `…Icon`, `twMerge`,
  hook ordering, no `_`-prefixed methods.
- **Tests:** backend — `SampleOutputPromptBuilderTest`, `SampleOutputCopilotGeneratorImplTest`
  (success / repair / still-invalid / object-and-array), `SampleOutputCopilotGraphQlControllerTest`
  (denied / allowed / disabled). Frontend — `SampleOutputCopilotBar` (gated render, generate→apply,
  invalid handling, replace-confirm); dialog wiring smoke where practical.
- **Verification:** server `spotlessApply` + ai-copilot module `check`; client `npm run check`.

## Architecture summary (units & boundaries)

| Unit | Responsibility | Depends on |
|------|----------------|------------|
| `SampleOutputPromptBuilder` | prompt → "return one JSON instance" | request prompt |
| `SampleOutputCopilotGeneratorImpl` | call model + parse-validate (object/array) + repair | ChatModel, JSON util |
| `SampleOutputCopilotGraphQlController` | mutation + IDOR guard | generator, Permission/ProjectWorkflow |
| `SampleOutputCopilotBar` (client) | prompt → generate → confirm → `onApply(jsonString)` | `useGenerateSampleOutput` |
| `OutputTabSampleDataDialog` wiring | place sample into the editor; existing Upload infers schema | `SampleOutputCopilotBar` |

Each unit has one purpose and a narrow interface. The bar is surface-agnostic; the only per-surface
code is the `onApply` that drops the JSON into the dialog's editor state — so a second surface
(should the dead schema-builder dialog ever go live) reuses it with no backend change.
