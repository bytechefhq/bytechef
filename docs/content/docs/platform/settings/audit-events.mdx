**Settings → Audit Events** records privileged actions across the platform. Recording is automatic - there is no per-resource opt-in and no way for a user to suppress an entry. The page requires the `ADMIN` authority and is Enterprise Edition.

## Finding an event

The screen has a filter sidebar on the left and a results table on the right.

| Filter | What it does |
|---|---|
| **Principal** | Match a single actor by login, e.g. `admin`. A failed sign-in is recorded under the name that was typed. |
| **Search data** | Free-text match against any recorded event data value. |
| **Event type** | Restrict to one event type from the dropdown; **All** clears it. |
| **From date** / **To date** | Bound the time window. |

A **Clear filters** link resets everything, and the page header shows a live **Filter by** summary of what is active. With no matches the table reads "No audit events match the current filters."

The results table lists **Date**, **Principal**, and **Event Type**. Clicking a row opens the **Audit Event Details** panel, showing the event type with its timestamp, the **Principal**, the **Event ID**, and the event's recorded **Data** as key/value pairs. When results span multiple pages, **Previous** / **Next** page through them.

## What an entry contains

Each entry is a row in `persistent_audit_event` plus its data map in `persistent_audit_event_data`:

- **Event ID** - the entry's identifier.
- **Principal** - the acting user's login.
- **Event type** - the verb, e.g. `WORKFLOW_UPDATED`, `CONNECTION_DELETED`. The full set is catalogued below.
- **Event date** - when it happened.
- **Data** - a string-to-string map of whatever the emitting site chose to record, typically the affected resource's id and name. Null values are dropped rather than stored.

Anything you want to filter on later has to be in the **Data** map - that is what **Search data** searches.

### Bulk operations

A single admin action that changes many resources is recorded as one entry that lists them. Reassigning every connection a former member owned, for example, records one `CONNECTION_REASSIGNED` entry whose data holds the affected `connectionIds` and their `connectionCount`.

### Failed audit writes

Writing an audit entry never fails or rolls back the operation it records. If an entry cannot be built or written, the operation still completes, the failure is logged, and the `bytechef_audit_failure` counter is incremented with a `reason` tag.

## Event types

The dropdown on the page is populated from the events your instance has actually recorded. The full set the platform can emit:

| Area | Event types |
|---|---|
| **Users** | `USER_CREATED`, `USER_ACTIVATED`, `USER_PASSWORD_CHANGED`, `USER_DELETED` |
| **Workspace membership** | `WORKSPACE_USER_ADDED`, `WORKSPACE_USER_REMOVED`, `WORKSPACE_USER_ROLE_UPDATED`, `WORKSPACE_USER_ENVIRONMENT_ROLE_UPDATED`, `WORKSPACE_USER_ENVIRONMENT_ROLE_REMOVED` |
| **Embedded membership** | `EMBEDDED_USER_ADDED`, `EMBEDDED_USER_ROLE_UPDATED`, `EMBEDDED_USER_REMOVED`, `EMBEDDED_USER_ENVIRONMENT_ROLE_UPDATED`, `EMBEDDED_USER_ENVIRONMENT_ROLE_REMOVED` |
| **Custom roles** | `CUSTOM_ROLE_CREATED`, `CUSTOM_ROLE_UPDATED`, `CUSTOM_ROLE_DELETED` |
| **Projects** | `PROJECT_CREATED`, `PROJECT_UPDATED`, `PROJECT_DELETED`, `PROJECT_VISIBILITY_CHANGED`, `PROJECT_ACCESS_GRANTED`, `PROJECT_ACCESS_REVOKED` |
| **Workflows** | `WORKFLOW_CREATED`, `WORKFLOW_UPDATED`, `WORKFLOW_DELETED` |
| **Deployments** | `DEPLOYMENT_CREATED`, `DEPLOYMENT_UPDATED`, `DEPLOYMENT_ENABLED`, `DEPLOYMENT_DISABLED`, `DEPLOYMENT_DELETED` |
| **Connections** | `CONNECTION_CREATED`, `CONNECTION_DELETED`, `CONNECTION_VISIBILITY_CHANGED`, `CONNECTION_ACCESS_GRANTED`, `CONNECTION_ACCESS_REVOKED`, `CONNECTION_CREDENTIALS_UPDATED`, `CONNECTION_REASSIGNED`, `WORKFLOW_PAUSED` |
| **API keys** | `API_KEY_CREATED`, `API_KEY_DELETED`, `WORKSPACE_API_KEY_CREATED`, `WORKSPACE_API_KEY_DELETED` |
| **Custom components** | `CUSTOM_COMPONENT_CREATED`, `CUSTOM_COMPONENT_UPDATED`, `CUSTOM_COMPONENT_DELETED`, `CUSTOM_COMPONENT_ENABLED`, `CUSTOM_COMPONENT_DISABLED`, `CUSTOM_COMPONENT_PUBLISHED` |
| **Data tables** | `DATA_TABLE_CREATED`, `DATA_TABLE_COLUMN_ADDED`, `DATA_TABLE_DELETED` |
| **Knowledge bases** | `KB_CREATED`, `KB_UPDATED`, `KB_DELETED`, `KB_ASSIGNED_TO_WORKSPACE`, `KB_REMOVED_FROM_WORKSPACE` |
| **API collections** | `API_COLLECTION_CREATED`, `API_COLLECTION_DELETED` |
| **MCP** | `MCP_PROJECT_CREATED`, `MCP_PROJECT_DELETED` |
| **Context store** | `CONTEXT_STORE_SOURCE_CREATED`, `CONTEXT_STORE_SOURCE_DELETED`, `CONTEXT_STORE_SOURCE_ENABLED`, `CONTEXT_STORE_SOURCE_DISABLED` |
| **AI Hub** | `AI_HUB_WORKSPACE_SETTINGS_UPDATED`, `AI_HUB_CHAT_CREATED`, `AI_HUB_CHAT_DELETED` |
| **Integrations (embedded)** | `INTEGRATION_CREATED`, `INTEGRATION_UPDATED`, `INTEGRATION_DELETED` |
| **Jobs** | `JOB_CREATED`, `JOB_STARTED`, `JOB_COMPLETED`, `JOB_FAILED`, `JOB_STOPPED` - recorded under the `SYSTEM` principal, with the job id in the data |
| **Access checks** | `PERMISSION_CHECK` - a guarded call that was denied or failed, or a successful call that changes something; successful reads are not recorded |

### Connection and project sharing events

These events are recorded under the login of the user who acted. Every entry also carries `method` (the operation that ran) and `result` (`SUCCESS`, `DENIED` or `ERROR`, or `ROLLED_BACK` when an enclosing transaction rolled back; an error adds `errorClass`), so an attempt the platform refused is recorded as well as one it allowed.

| Event | Recorded when | Data |
|---|---|---|
| `CONNECTION_CREATED` | A workspace or organization connection is created. | `connectionId`, `workspaceId` (workspace connections only), `visibility` as stored |
| `CONNECTION_DELETED` | A workspace or organization connection is deleted. | `connectionId` |
| `CONNECTION_VISIBILITY_CHANGED` | A connection's visibility is changed. | `connectionId`, `workspaceId`, `fromVisibility`, `toVisibility` |
| `CONNECTION_ACCESS_GRANTED` | A member is named on a private connection. | `connectionId`, `workspaceId`, `targetUserId` |
| `CONNECTION_ACCESS_REVOKED` | A member's access to a private connection is removed. | `connectionId`, `workspaceId`, `targetUserId` |
| `CONNECTION_CREDENTIALS_UPDATED` | A connection's credentials are replaced. No credential values are recorded. | `connectionId` |
| `CONNECTION_REASSIGNED` | An organization admin gives a connection a new owner. | `connectionId`, `workspaceId`, `newOwnerUserId`; for a bulk reassignment, `previousOwnerUserId`, `connectionIds` and `connectionCount` instead of `connectionId` |
| `WORKFLOW_PAUSED` | A deployed workflow run is refused because a connection it uses is not active. The `result` is `ERROR`. | `jobPrincipalId` (the project deployment), `workflowId`, `connectionIds`, `connectionStatuses` |
| `PROJECT_VISIBILITY_CHANGED` | A project's visibility is changed. | `workspaceId`, `projectId`, `fromVisibility`, `toVisibility` |
| `PROJECT_ACCESS_GRANTED` | A member is named on a private project. | `workspaceId`, `projectId`, `targetUserId` |
| `PROJECT_ACCESS_REVOKED` | A member's access to a private project is removed. | `workspaceId`, `projectId`, `targetUserId` |

Users are recorded by id, never by email address. `WORKFLOW_PAUSED` for a manual run is recorded under the user who started it; for a run fired by a webhook trigger it is recorded under `anonymousUser`, the principal of the webhook request, and under `SYSTEM` where no security context exists.

## What is not logged

- **Secret values.** The log records that a credential was created or deleted, by whom, and when - never the secret material.
- **Workflow execution data.** Execution inputs and outputs live in execution history, so the audit log stays focused on privileged administrative actions rather than data flow.

## Retention

Audit entries persist in your operational database. A scheduled job deletes entries older than the retention window:

| Property | Default | Meaning |
|---|---|---|
| `bytechef.audit.retention-days` | `365` | Age at which an entry is purged. |
| `bytechef.audit.retention-cron` | `0 0 2 * * *` | When the purge runs - daily at 02:00 local time. |

A `retention-days` of zero or less disables the purge rather than deleting the whole trail. Retention is instance-wide, not per workspace.

## Masking principals

Set `bytechef.audit.mask-principals` to `true` to mask principals when entries are read through the API, e.g. `a***@example.com`. The stored entries are unchanged, and the **Principal** filter still matches the full, unmasked value.
