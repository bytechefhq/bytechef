Self-hosting runs the ByteChef server on infrastructure you operate: Docker, Kubernetes, AWS,
Azure, Google Cloud or DigitalOcean. You control where data is stored, how the network is exposed,
and every instance-wide setting. This section covers installation, configuration, operation and
the deployment architecture.

## Deployment models

The same server image runs as one or more long-lived server instances. The Enterprise Edition
adds a single-shot runner.

### The server

One process carrying the workflow engine, every domain service, and the HTTP API. PostgreSQL is the
only hard dependency; Redis is optional. This is the recommended starting point for every
deployment. Start at
[Local Docker](/platform/use-bytechef/self-hosted/installation/local-docker).

To handle more load, run several instances against the same database. Align these settings first:
a shared encryption key, a shared message broker, shared file storage, a fixed remember-me key, and
migrations owned by one instance. More than one coordinator also needs Enterprise Edition, a shared
session store and cache provider, and a clustered scheduler. See
[Running multiple instances](/platform/use-bytechef/self-hosted/configuration#running-multiple-instances).

### Single-shot

The [runtime job runner](/platform/use-bytechef/self-hosted/runtime-job) boots, executes exactly one
workflow, and exits with the workflow's status. No database, no broker, no triggers - for batch runs
whose schedule already lives in Airflow, a CI pipeline, or a Kubernetes `CronJob`. Enterprise Edition.

## Supported substrates

| Substrate | Recommended for | Notes |
|---|---|---|
| [Docker / Docker Compose](/platform/use-bytechef/self-hosted/installation/local-docker) | Dev, demo, and small production | A reference `docker-compose.yml` is shipped with the platform, pulling `docker.bytechef.io/bytechef/bytechef`. |
| [Kubernetes](/platform/use-bytechef/self-hosted/installation/kubernetes) | Production deployments of any size | A Helm chart for the monolith lives at `kubernetes/helm/bytechef`. |
| [AWS](/platform/use-bytechef/self-hosted/installation/aws-ec2) | Cloud-native deployments on AWS | EC2 or ECS. In Enterprise Edition, SQS can serve as the message broker, S3 as file storage, and EventBridge Scheduler as the scheduler backend. |
| [Google Cloud](/platform/use-bytechef/self-hosted/installation/google-cloud) | Cloud-native deployments on GCP | Cloud Run or Compute Engine, with PostgreSQL on Cloud SQL. |
| [Azure](/platform/use-bytechef/self-hosted/installation/azure) | Cloud-native deployments on Azure | Container Apps, with PostgreSQL on Azure Database for PostgreSQL. |
| [DigitalOcean](/platform/use-bytechef/self-hosted/installation/digitalocean) | Small to mid-size deployments | App Platform or a Droplet, with DigitalOcean Managed PostgreSQL. |

The Helm chart templates the deployment, service, ingress, ConfigMap, Secret, service account, and an
HPA. Note that it ships `replicaCount: 1` and sets no broker or cache variables, so the default values
run the in-memory broker. Raising `replicaCount` (or enabling the HPA) on its own gives you replicas
that cannot hand each other work. Add the shared-instance settings under `env.normal` first, per
[Running multiple instances](/platform/use-bytechef/self-hosted/configuration#running-multiple-instances).

## Your perimeter, your secrets

- **Credentials never leave your network.** Connection credentials are encrypted at rest in your own
  database with a key you supply - see
  [Encryption of stored credentials](/platform/use-bytechef/self-hosted/configuration#encryption-of-stored-credentials).
- **Telemetry export is opt-in.** OpenTelemetry export ships **disabled**; each signal stays off
  until you set its endpoint and enable flag
  ([Observability](/platform/use-bytechef/self-hosted/management/observability)).
- **Product analytics and in-app guides are on in the published image.** `bytechef.analytics.enabled`
  (PostHog) and `bytechef.user-guiding.enabled` (UserGuiding tutorials) are `false` in the base
  configuration, but the `prod` profile the published container image runs sets both to `true`. Set
  `BYTECHEF_ANALYTICS_ENABLED=false` and `BYTECHEF_USER_GUIDING_ENABLED=false` to turn them off.
- **You choose the AI providers.** You decide which providers receive prompts and where their keys
  live.
- **Configuration is externalized.** Instance-wide server options are set through environment
  variables or property files, so the same image behaves differently per environment based on what
  you pass in ([Configuration](/platform/use-bytechef/self-hosted/configuration)).
