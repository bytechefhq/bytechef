ByteChef keeps a working sample for each way you extend or embed the platform. Every repository builds or checks
locally, and its README walks through deploying it. Each table links the page that explains the feature.

## Code workflows

A whole project or integration defined in code - see [Code Workflows](/platform/automation/build/workflows/code-workflows).
Each sample has a local check that evaluates the file the way the server does and runs its tasks once.

|---|---|---|---|

| **Embedded code integration** | [bytechef-embedded-integration-sample-code-workflow-java](https://github.com/bytechefhq/bytechef-embedded-integration-sample-code-workflow-java) | [bytechef-embedded-integration-sample-code-workflow-javascript](https://github.com/bytechefhq/bytechef-embedded-integration-sample-code-workflow-javascript) | [bytechef-embedded-integration-sample-code-workflow-python](https://github.com/bytechefhq/bytechef-embedded-integration-sample-code-workflow-python) |

Each sample includes a workflow started by the Gmail **New Email** trigger, one that calls the Gmail **Search Email**
action, and `notifySlackOnNewEmail`, which posts each new email to Slack through a declared `slack` connection and
picks its channel from Slack's own `channel` input.

- **Automation project** - a project deployed to Automation → Projects; it also has a workflow that takes a `name` input
  and returns a greeting. See [Code Workflows](/platform/automation/build/workflows/code-workflows).
- **Embedded catalog code project** - a catalog project run by reference for your connected users; its
  `greetOnRequest` workflow has a Request trigger. See
  [Automation Code Workflows](/platform/embedded/build/automations/automation-code-workflows).
- **Embedded code integration** - an integration built on the Gmail component, so its Gmail calls need no declared
  connection. See [Code Integrations](/platform/embedded/build/code-integrations).

### Checking and deploying a code workflow sample

Every sample's README has the full steps. In short:

| Sample | Local check | File to deploy | Deploy endpoint | API key |
|---|---|---|---|---|
| Automation project, JavaScript | `npm run check` | `src/sample_code_project.js` | `POST /api/automation/v1/projects/deploy?workspaceId=<id>` | Workspace API key |
| Automation project, Python | `python3 scripts/check.py src/sample_code_project.py name=Ada` | `src/sample_code_project.py` | same | same |
| Automation project, Java | `./gradlew build` | `build/libs/sample-code-project-java-1.0.0.jar` | same | same |
| Catalog code project, JavaScript | `npm run check` | `src/sample_catalog_code_project.js` | `POST /api/embedded/v1/automation-project-code-workflows/deploy` | Embedded API key |
| Catalog code project, Python | `python3 scripts/check.py src/sample_catalog_code_project.py` | `src/sample_catalog_code_project.py` | same | same |
| Catalog code project, Java | `./gradlew build` | `build/libs/sample-catalog-code-project-java-1.0.0.jar` | same | same |
| Code integration, JavaScript | `npm run check` | `src/sample_code_integration.js` | `POST /api/embedded/v1/integration-code-workflows/deploy` | Embedded API key |
| Code integration, Python | `python3 scripts/check.py src/sample_code_integration.py` | `src/sample_code_integration.py` | same | same |
| Code integration, Java | `./gradlew build` | `build/libs/sample-code-integration-java-1.0.0.jar` | same | same |

The JavaScript and Python checks evaluate the file the way the server does and run each task once against a stub
context; they need only Node.js or Python 3.9 or later and install nothing. The Java samples need JDK 25 and compile
against the ByteChef SDK jars in their `libs/` folder. The file part is `projectFile` on the two project endpoints and
`integrationFile` on the integration endpoint, and every endpoint takes the environment from the `X-ENVIRONMENT`
header (`PRODUCTION` when absent). You can also upload the file from the UI: **Import Code Project** on Automation →
Projects or Embedded → Automations, and **Import Code Integration** on Embedded → Integrations. These menu items,
like code workflows themselves, are Enterprise Edition only.

The JavaScript samples also carry a TypeScript version checked with `npm run check:ts`, and the Python samples a
`mypy --strict` type check. Both need the `@bytechef/workflow-api` or `bytechef-workflow-api` type package, which is
not published yet; see [Typed authoring](/platform/automation/build/workflows/code-workflows#typed-authoring) for
installing it from the ByteChef repository.

## Custom components

Your own component, uploaded and used like a built-in one - see
[Custom Components](/platform/settings/components/custom-components), which quotes each sample and walks through
building, checking and deploying it.

| Language | Repository | Shows |
|---|---|---|
| Java | [bytechef-sample-custom-component-java](https://github.com/bytechefhq/bytechef-sample-custom-component-java) | A Gradle project that builds a jar with one component, `sampleCustomComponentJava`, and one action. See [the Java sample](/platform/settings/components/custom-components#example-the-java-sample). |
| JavaScript | [bytechef-sample-custom-component-javascript](https://github.com/bytechefhq/bytechef-sample-custom-component-javascript) | One source file with one component, `sampleCustomComponentJavaScript`, and one action. See [the JavaScript sample](/platform/settings/components/custom-components#example-the-javascript-sample). |

There is no Python custom component sample; the Custom Components page has a
[Python example](/platform/settings/components/custom-components#a-python-component).

every workflow and project there is published as a template you can preview and import. See
[Templates](/platform/automation/build/workflows/templates).
