This page defines the main terms used in the ByteChef platform.

## Projects

A project is a container for one or more workflows. Projects group related workflows so they can be managed, published and deployed together. You can create, edit, duplicate, import and delete projects.

## Workflows

A workflow is a trigger followed by a sequence of steps that automates a process. Steps are actions of components and flow controls, such as conditions, loops and branches, that add logic to the sequence.

## Components

A component is a building block that wraps one external service or one capability of the platform. Workflows use components to interact with external services or to perform specific tasks.

A component is made up of actions and triggers. Most components also define a connection, which holds the credentials and settings their actions and triggers need to reach the external service. Some components expose cluster elements: the models, tools and memory that an AI agent step can be wired to.

Every built-in component is listed, action by action, in the [component reference](/reference/components).

## Connections

A connection links a component to an external service or application. It holds the information the component needs to call the service, such as authentication details, the base URL and other properties.

## Triggers

A trigger is the event that starts a workflow. Examples are a new email, a change in a database, a webhook call or a scheduled time.

## Actions

An action is an operation that a component performs. Actions send data to an external service, retrieve information or transform data within the workflow. For example, an action can send an email, update a database record or fetch user details from an API.
