---
title: Limits and Concurrency
description: Reference for the execution limits that apply to an embedded deployment, and the per-customer limits you enforce outside ByteChef.
---

All connected users of an embedded deployment run their workflows on the same ByteChef engine. The engine applies deployment-wide concurrency limits and timeouts. It does not apply limits per connected user or per tenant.

## Deployment-wide limits

These limits apply to all workflow runs on a node, regardless of which connected user started them. Configure them with environment variables on the ByteChef server.

| Limit | Environment variable | Default | Behavior when reached |
|---|---|---|---|
| Concurrent workflow tasks | `BYTECHEF_WORKER_TASK_SUBSCRIPTIONS_DEFAULT` | `10` | Further tasks wait for a free slot. |
| Concurrent synchronous executions | `BYTECHEF_WORKER_TASK_SYNC_CONCURRENCY_LIMIT` | `5` | Further synchronous callers wait for a free slot. |
| Task timeout | `BYTECHEF_WORKER_TASK_DEFAULT_TIMEOUT` | 24 hours | The task fails. A task's own `timeout` parameter overrides the default. |
| Polling trigger interval | `BYTECHEF_COORDINATOR_TRIGGER_POLLING_CHECK_PERIOD` | `5` (minutes) | Polling triggers check for new data at this interval. |
| Request trigger wait | - | 5 minutes | The run is marked failed and the caller receives an error. See [Request Triggers](/platform/embedded/build/request-triggers#the-response). |
| External invocation log retention | `BYTECHEF_EXTERNAL_INVOCATION_LOG_RETENTION_DAYS` | `90` (days) | Older [external invocation](/platform/embedded/monitor/external-invocations) records are deleted. |

For the full list of server settings, see [Environment Variables](/platform/use-bytechef/self-hosted/configuration/environment-variables).

## Limits that are not enforced

ByteChef does not limit, per connected user or per tenant:

- the number of API requests, App Events or Request trigger calls;
- the number of workflow runs, or how many run at the same time;
- the execution time a connected user's workflows consume.

Connected users therefore share worker capacity. A connected user who starts many runs increases the queue time of other connected users' runs. Data stays isolated: a run cannot read another tenant's data, connections or execution history. See [Tenant-isolated security](/platform/embedded/get-started/white-label-execution#tenant-isolated-security).

## Enforcing per-customer limits

Apply per-customer limits in your own application, before requests reach ByteChef.

| Control | Where | Purpose |
|---|---|---|
| Rate limit per customer | Your API gateway or backend | Caps calls to the embedded API for each customer. Your gateway identifies the customer before ByteChef does. |
| Throttle App Events | Your backend | Each App Event starts every workflow subscribed to it for that connected user, so one event can start several runs. |
| Bound workflow work | Workflow design | Use pagination and batch sizes in components so that one run does not process an unbounded data set. |
| Monitor volume per customer | [Workflow Executions](/platform/embedded/monitor/workflow-executions) | Executions are attributed to connected users, so you can identify the customers that generate the most load. |

Use asynchronous triggers (App Events, webhooks, polling or scheduled triggers) for workflows that loop over large data sets or call slow providers. A Request trigger with **Await Workflow and Respond** holds the HTTP connection open until the workflow finishes, up to the 5-minute limit.

## Plan limits

<Callout type="warn" title="Coming soon">Per-tenant plan limits are not available. A deployment has no per-tenant rate, concurrency, cost or quota limits.</Callout>

Plan limits add per-tenant enforcement: rate limits, a maximum number of concurrently running jobs, a monthly cost cap, and quotas for workspaces, members and storage. Rate and concurrency rejections return HTTP `429` with a `Retry-After` header. Quota rejections return HTTP `403`. Self-hosted deployments default to no limits. See [Plan Limits](/platform/use-bytechef/self-hosted/configuration/plan-limits).
