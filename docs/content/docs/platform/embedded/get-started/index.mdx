ByteChef **Embedded** lets you offer third-party integrations inside your own SaaS product. Your end users authorize the services they already use (Gmail, Slack, HubSpot, AWS S3 and 200+ more) from your UI, and ByteChef runs the workflows you publish with each user's own credentials. You build the integrations once in ByteChef; your product shows them through the `@bytechef/embedded` React SDK or calls them through the embedded REST API.

<Callout title="Enterprise Edition only">
    Embedded requires an Enterprise Edition deployment (`bytechef.edition=EE`). The open-source (CE) build does not expose the `/embedded` UI or APIs.
</Callout>

### The in-app Getting Started checklist

In the **Development** environment, an admin of an EE instance sees **Embedded** → **Getting Started** in the sidebar until the checklist is complete. It tracks four steps against your instance's real data:

1. **Create an API key** - the key your backend uses to call the embedded API.
2. **Set up your first integration** - create an integration, publish a version, create a configuration in Development and enable it.
3. **Connect a test user** - add a connected user, provision the integration for them and connect their account.
4. **Make your first call** - run the generated `curl` command, which executes a component action for the test user, and the page confirms when the call arrives.

## Capabilities

| Capability | Description |
|---|---|
| **200+ pre-built components** | Connectors for the SaaS apps your users already work with. |
| **Embeddable React SDK** | `useConnectDialog` opens a connect-and-authorize flow, `useActivationDialog` and `ActivationDialog` activate an automation template, `AutomationHub` embeds a catalog of automation templates, `IntegrationMarketplace` embeds an integration catalog, and `EmbeddedWorkflowBuilder` embeds the workflow editor. See [Installing the SDK](/platform/embedded/get-started/initial-setup/installing-the-sdk). |
| **Per-user connection store** | Each end user has their own credentials, kept separately per environment (Development, Staging, Production). |
| **App Events** | Define events in your product (for example `user.signed_up` or `order.placed`) and start the workflows that subscribe to them. |
| **Permission expressions** | Limit integrations and individual workflows to a subset of connected users with a SpEL expression. |
| **AI workflow generation** | Generate a workflow for a connected user from a natural-language prompt with `POST /api/embedded/v1/automation/workflows/generate`. Requires AI Copilot (`BYTECHEF_AI_COPILOT_ENABLED=true`). |
| **Workflow execution history** | Every run, step by step, in the ByteChef admin UI under **Embedded** → **Workflow Executions**. Execution history is not part of the public API. |
| **MCP Servers** | Expose components and workflows as Model Context Protocol tool servers for AI agents. See [MCP Servers](/platform/embedded/configure/mcp-servers). |

## How the pieces fit together

```
Your product (web app, mobile, backend)
        │
        │ 1. Backend signs a short-lived JWT using a Signing Key
        │ 2. Frontend passes JWT to @bytechef/embedded
        │
        ▼
   ByteChef Embedded
   ├── Integrations         - integrations you build for your customers
   ├── Configurations       - published integration versions per environment
   ├── App Events           - events your product fires to trigger workflows
   ├── Automations          - automation templates connected users activate
   ├── MCP Servers          - components and workflows exposed as MCP tools
   ├── Connected Users      - your end users (identified by externalUserId)
   ├── Connections          - per-user credentials for each integration
   └── Executions           - history of every workflow run
```

Traffic flows in two directions:

- **Your product to ByteChef:** authenticate end users with a JWT signed by a Signing Key, fire App Events that start workflows, and call the embedded API server-to-server with an API Key.
- **ByteChef to third-party services:** run your published workflows with each connected user's credentials.

## Embedded or Automation

ByteChef has two modes:

| Mode | Use it when |
|---|---|
| **Automation** | You run workflows for yourself or your internal team. You own the connections and the workflows. |
| **Embedded** | You ship integrations to your customers inside your product. Each customer has their own connections and activates the integrations and automations you publish. |
