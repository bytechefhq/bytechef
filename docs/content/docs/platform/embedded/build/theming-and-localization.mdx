The embedded surfaces render inside your product: the Automation Hub, the Integration Marketplace and the workflow builder in an iframe, and the Connect and activation dialogs directly in your page. This page lists which styling options each surface accepts, and which parts of the UI are fixed.

## Styling options by surface

| Surface | How it renders | Styling options |
|---|---|---|
| [Automation Hub](/platform/embedded/build/automations/automation-hub) | iframe (`automation-hub.html`) | `theme` prop. Also applies to the workflow builder and the dialogs that the hub opens. |
| [Integration Marketplace](/platform/embedded/build/integration-marketplace) | iframe (`integration-marketplace.html`) | `theme` prop. `theme.mode` is passed to the Connect dialog that the marketplace opens. |
| `EmbeddedWorkflowBuilder` | iframe (`workflow-builder.html`) | None. Renders the default light theme. |
| Connect dialog (`useConnectDialog`) | In your page | `mode` option and `--bytechef-dialog-*` CSS variables. |
| Activation dialog (`useActivationDialog`) | In your page | `mode` option and `--bytechef-dialog-*` CSS variables. |

## The `theme` prop

`AutomationHub` and `IntegrationMarketplace` accept the same `theme` object. Every key is optional. A key you do not set keeps the default value.

```tsx
<AutomationHub
    jwtToken={jwtToken}
    theme={{
        borderRadius: '0.5rem',
        fontFamily: 'Inter, system-ui, sans-serif',
        mode: 'dark',
        primaryColor: '#2563eb',
    }}
/>
```

| Key | Type | Effect |
|---|---|---|
| `mode` | `'dark' \| 'light'` | Color scheme. Any value other than `'dark'` renders light. |
| `primaryColor` | color | Buttons, focus rings and brand accents. The text color on top of it is set to black or white, whichever has more contrast. |
| `fontFamily` | string | Value of the `font-family` used by the surface. |
| `borderRadius` | length | Corner radius. Accepts `px`, `rem`, `em` or `%`, for example `8px` or `0.5rem`. |
| `surfaceColor` | color | Page background. |
| `cardColor` | color | Cards, dialogs and popovers. |
| `activeBorderColor` | color | Border of enabled automation cards. |
| `enableColor` | color | **Enable** button. |
| `disableColor` | color | **Disable** button. |
| `onAccentColor` | color | Text on accent-colored surfaces. |
| `segmentColor` | color | Selected item in segmented controls. |
| `cssVariables` | `Record<string, string>` | Additional CSS custom properties, for example `{'--my-variable': '4px'}`. Keys that do not start with `--` are ignored. |

### Validation

- A color is a hex value (`#2563eb`, `#25e`) or any value the browser accepts as a CSS color (`rgb(37 99 235)`, `rebeccapurple`). An unrecognized color is ignored.
- A `borderRadius` that is not a number followed by `px`, `rem`, `em` or `%` is ignored.
- `cssVariables` values are not validated.

### Fonts

The surface renders in an iframe, so `@font-face` rules declared in your page do not apply inside it. Use a font that the iframe can load without your stylesheet, such as a system font stack.

### Updating the theme

When the `theme` prop changes, the component sends the new values to the iframe. The iframe does not reload.

## Styling the Connect and activation dialogs

The Connect dialog and the activation dialog render in your page, not in an iframe.

### `mode`

Both `useConnectDialog` and `useActivationDialog` accept `mode: 'dark' | 'light'`. The default is `'light'`. `'dark'` switches the default surface, border, text and hover colors to a dark palette.

### CSS variables

The dialogs read the following CSS custom properties. Set them on `:root` or on any ancestor of the dialog. A variable you do not set uses the default for the current `mode`.

| Variable | Applies to | Light default | Dark default |
|---|---|---|---|
| `--bytechef-dialog-surface` | Dialog background | `#fff` | `#111827` |
| `--bytechef-dialog-surface-raised` | Raised areas inside the dialog | `#fff` | `#1f2937` |
| `--bytechef-dialog-border` | Borders | `#e5e7eb` | `#374151` |
| `--bytechef-dialog-text` | Text | `#0a0a0a` | `#f9fafb` |
| `--bytechef-dialog-text-muted` | Secondary text | `#6b7280` | `#9ca3af` |
| `--bytechef-dialog-hover` | Hover backgrounds | `#f1f5f9` | `#374151` |
| `--bytechef-dialog-primary` | Primary buttons and accents | `#1071e5` | `#1071e5` |
| `--bytechef-dialog-primary-hover` | Primary button hover | `#0b50a3` | `#0b50a3` |
| `--bytechef-dialog-primary-foreground` | Text on primary buttons | `#fff` | `#fff` |

```css
:root {
    --bytechef-dialog-primary: #2563eb;
    --bytechef-dialog-primary-hover: #1d4ed8;
    --bytechef-dialog-surface: #ffffff;
}
```

When the Automation Hub opens a dialog, it sets these variables from its `theme`: `primaryColor` sets the three `primary` variables, `cardColor` sets the surface and text variables, `surfaceColor` sets the hover variable, and `activeBorderColor` sets the border variable.

## Localization

<Callout type="warn" title="Coming soon">Localization of the embedded surfaces is not available. No surface accepts a locale.</Callout>

All embedded surfaces display their labels, messages and validation errors in English. No component or hook accepts a locale or replacement text.

## Fixed elements

The following parts of the embedded experience cannot be configured from the SDK.

| Element | Behavior |
|---|---|
| Labels and messages | Fixed text, in English, on every surface. This includes validation messages in the Connect dialog. |
| Connect dialog footer | Always shows a **Powered by ByteChef** link. |
| Standalone workflow builder appearance | `EmbeddedWorkflowBuilder` has no `theme` prop and renders the default light theme. To apply a theme to the builder, open it from the Automation Hub. |
| Engine error messages | Shown in English in execution history, as produced by the workflow engine and the components. |
| Component documentation links | Component help in the workflow builder links to the ByteChef documentation. |

## Host names and URLs

The iframes load from the `baseUrl` you pass to the SDK components, and the APIs and webhook URLs are served by the same ByteChef deployment. On a self-hosted deployment you choose its host names:

| Variable | Controls | Default |
|---|---|---|
| `BYTECHEF_PUBLIC_URL` | Public base URL of the ByteChef UI, used for OAuth2 redirect URIs and mail links | `http://127.0.0.1:8080` |
| `BYTECHEF_WEBHOOK_URL` | URL template of the webhook URLs that ByteChef registers with trigger providers and shows in the workflow builder | `BYTECHEF_PUBLIC_URL/webhooks/{id}` |

Set them, and the `baseUrl` you pass to the SDK, to a domain you control (for example `https://automations.example.com`) to keep ByteChef host names out of the URLs your customers see. The values apply to the whole deployment; they cannot be set per connected user. See [Environment Variables](/platform/use-bytechef/self-hosted/configuration/environment-variables).
