title: "Connections"
description: "Create and manage connections that store credentials for third-party services."
---

A connection stores the credentials and configuration that ByteChef uses to call an external service, such as Slack, Google Drive, or Salesforce. You create a connection once and select it in any workflow step of that component. Workflow builders create and maintain connections; administrators can update credentials on any connection in the workspace.

## Key features

- **Central management** - View, edit, and monitor all connections on the **Connections** page.
- **Reuse** - Use one connection in many workflows.
- **Encryption** - Credentials are encrypted at rest with AES-GCM, an authenticated encryption mode.
- **Guided setup** - The connection dialog shows the fields and the authorization flow that each service requires.
- **Environments** - Each connection belongs to one environment (development, staging, or production).

## Create a connection

{/* TODO screenshot: Connections page - connection list with the Create Connection dialog open showing the component picker and auth fields */}

1. Click **Connections** in the main sidebar.
2. Click **New Connection**.
3. Select the component (service) to connect to.
4. Enter a **Name** for the connection, for example `Company Slack - Marketing`.
5. Fill in the credential fields the service requires. Depending on the service, this is an API key, a token, a username and password, or an OAuth 2.0 authorization (see [Authentication](/platform/automation/build/connections/authentication)).
6. Click **Save**. For OAuth 2.0 services, click **Next**, select the scopes, and click **Connect** instead.

The **Environment** field in the dialog shows the environment the connection is created in. Connections are scoped to the currently selected environment. Use the environment selector in the left sidebar header to switch environments.

<Callout type="warn" title="Coming soon">
  External credential stores are not available in the latest released version of ByteChef. When they are, an administrator can configure an external secret backend, and the create dialog shows a **Credential storage** selector. With a non-default store, you can turn on **Register existing credential** and reference a secret in that store by its path or UUID instead of entering the credentials in ByteChef. The selector appears only when more than one credential store is available, and it cannot be changed after the connection is created.
</Callout>

## Manage connections

The **Connections** page lists every connection with its component icon, name, tags, creation date, and two status badges:

| Badge | Values | Meaning |
|---|---|---|
| Usage | **Active**, **Not Active** | **Active** means at least one workflow uses the connection. |
| Credential status | **VALID**, **INVALID** | **INVALID** means the service rejected the stored credentials. Workflows that use the connection are blocked until new credentials are saved. |

Use the left sidebar to filter the list by **Components** or by **Tags**.

Each connection has an ellipsis menu with the following actions:

| Action | Description |
|---|---|
| **Edit** | Rename the connection and change its properties. The dialog also has an **Update credentials** button (see below). |
| **Disconnect from all** | Detach the connection from every workflow that uses it. Shown only for **Active** connections. |
| **Delete** | Permanently remove the connection. Disabled while the connection is **Active**; disconnect it from all workflows first. |

Edit tags inline on the connection row.

### Update credentials

To replace the stored credentials without recreating the connection:

1. Open the connection's ellipsis menu and click **Edit**.
2. Click **Update credentials**.
3. Enter the new credentials. For OAuth 2.0 connections, run the authorization flow again.
4. Click **Update credentials** to save.

Only the user who created the connection and workspace administrators can update its credentials. When the credential status is **INVALID**, the dialog shows a **These credentials were rejected** alert.

<Callout type="warn" title="Coming soon">
  Connection visibility is not available in the latest released version of ByteChef. When it is, an Enterprise Edition connection carries a **visibility** scope shown as a badge on its row, and a **Change visibility** control offers **Shared with workspace** (the default), **Private**, and **Specific people**. **Specific people** grants named workspace members access to a connection that stays private to everyone else.
</Callout>

## Authentication methods

| Method | Description |
|---|---|
| [OAuth 2.0](/platform/automation/build/connections/authentication/oauth2) | You sign in on the service's own page and grant access; ByteChef never sees your password. |
| [API Key](/platform/automation/build/connections/authentication/api-key) | A secret key from the service that you paste into ByteChef. |
| [Bearer Token](/platform/automation/build/connections/authentication/bearer) | A token sent in the `Authorization` header. |
| [Basic Auth](/platform/automation/build/connections/authentication/basic) | A username and password, typically for internal or legacy systems. |
