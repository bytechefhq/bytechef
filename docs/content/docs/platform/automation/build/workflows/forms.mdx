A **form** is a hosted web page that starts a workflow. You define the fields in the workflow trigger, deploy the workflow, and share the form link. Each submission triggers the workflow, and the submitted values are available to later steps as typed data. Use forms to collect input from people outside ByteChef without building your own UI.

Forms are provided by the [**Form**](/reference/components/form_v1) component. For the generated list of properties and the JSON example, see the [component reference](/reference/components/form_v1).

## Use cases

- **Intake** - contact requests, support tickets, lead capture, job applications.
- **Surveys and feedback** - collect typed answers and route them to other systems.
- **Internal data entry** - push records into a CRM, a spreadsheet or a [data table](/platform/automation/data/data-tables).
- **File collection** - accept uploads as the first step of a processing workflow.

For a conversational front end, use [Chats](/platform/automation/deploy/chats). To pause a running workflow for a person's decision, use [Human-in-the-Loop](/platform/automation/build/workflows/human-in-the-loop).

## Triggers

The Form component has two triggers. Both are static webhooks with the same properties and output.

| Trigger | Behavior |
|---|---|
| **New Form Request** | Runs the workflow synchronously. The submission request waits until the workflow finishes. |
| **New Form Request (Respond Immediately)** | Responds to the submitter at once; the workflow runs in the background. |

A synchronous run cannot pause. If the workflow contains a step that can pause it, such as an approval, use **New Form Request (Respond Immediately)**.

## Prerequisites

- The server public URL (`bytechef.public-url`, environment variable `BYTECHEF_PUBLIC_URL`) must be reachable by the people who fill in the form, for example your domain or a tunnel for local development.

## Build a form

{/* TODO screenshot: workflow editor form trigger/step configuration - the form fields builder and page options */}

1. In the workflow editor, click the trigger and search for **Form**.
2. Select **New Form Request** or **New Form Request (Respond Immediately)**.
3. Set **Form Title**, **Form Description** and **Button Label**. They control the page heading, the subtitle and the submit button.
4. Add fields under **Form Inputs**. For each field, select a **Field Type** and enter a **Field Name**. The field name is the key of the submitted value.
5. In later steps, reference the submitted values from the trigger output, for example `${trigger_1.body.email}` and `${trigger_1.submittedAt}`.
6. Deploy the workflow. In the deployment's workflow list, click the **Open form** icon to open the hosted form page.

## Share the form

The hosted form page has the path `/form/{environmentId}/{id}`. The form submits to the trigger's webhook URL, `/webhooks/{id}`, which uses the same id. After a successful submission the page shows **Thank you!** and **Your response has been submitted.** If the request fails, the page shows the error. The page does not display the workflow output.

## Reference

### Page properties

| Property | Type | Default | Description |
|---|---|---|---|
| **Form Title** | Text | | Main page title. |
| **Form Description** | Text | | Subtitle under the title. Use `\n` or `<br>` for line breaks. |
| **Button Label** | Text | | Label of the submit button. |
| **Ignore Bots** | Boolean | `false` | Ignores requests from bots and link previewers, matched on the `User-Agent` header. |
| **Use Workflow Timezone** | Boolean | `false` | When `false`, the server overwrites `submittedAt` with its own UTC timestamp. When `true`, the submitted value is kept. |
| **Append Attribution** | Boolean | `true` | Shows a "powered by" footer on the form. |
| **Custom Form Styling (CSS)** | Text area | | CSS that overrides the default form styles. |
| **Form Inputs** | Array | | The form fields. See the next table. |

### Field properties

| Property | Applies to | Description |
|---|---|---|
| **Field Type** | All | One of the types in [Field types](#field-types). |
| **Field Label** | All | Label shown next to the field. |
| **Field Name** | All except Custom HTML | Key of the submitted value in `body`. |
| **Field Description** | All | Help text for the field. |
| **Placeholder** | Input, Email, Number, Password, Textarea | Placeholder text. |
| **Default value** | All | Initial value. For Custom HTML, a multi-line box that holds the HTML to render. |
| **Field Options** | Radio Button, Select | List of **Label** / **Value** pairs. |
| **Multiple Choice** | Select | Allows more than one selection. Default `false`. |
| **Min selection** / **Max selection** | Select with Multiple Choice | Minimum and maximum number of selected options. |
| **Required** | All | Makes the field mandatory. Default `false`. |

### Field types

| Field type | Description | Output type |
|---|---|---|
| **Input** | Single-line text. | string |
| **Textarea** | Multi-line text. | string |
| **Email** | Text validated as an email address. | string |
| **Number** | Numeric input. | number |
| **Password** | Masked text. | string |
| **Checkbox** | Boolean value. | boolean |
| **Date Picker** | Date. | date |
| **Datetime Picker** | Date and time. | date-time |
| **Radio Button** | One option from **Field Options**. | string |
| **Select** | Drop-down; optionally multiple choice. | string, or array of strings with **Multiple Choice** |
| **File** | File upload. | file entry |
| **Hidden Field** | Preset value not shown to the visitor. | string |
| **Custom HTML** | HTML rendered between fields, for headings or instructions. Collects no value. | none |

### Output

The trigger output is generated from the field definitions:

- `submittedAt` - the submission timestamp.
- `body` - an object with one property per field, keyed by **Field Name** and typed as in the table above.

For example, `${trigger_1.body.dueDate}` resolves to a date and `${trigger_1.body.tags}` (a multiple-choice Select) resolves to an array, without a conversion step.

### Example

This trigger defines a contact form with a name, an email address and a multiple-choice Select. In the workflow definition, **Field Type** is stored as a number: `6` is Input, `8` is Email and `7` is Select. The full list of values is in the [component reference](/reference/components/form_v1).

```json
{
  "name": "trigger_1",
  "type": "form/v1/newFormRequestRespondImmediately",
  "parameters": {
    "formTitle": "Contact us",
    "formDescription": "We reply within one business day.",
    "buttonLabel": "Send",
    "inputs": [
      {"fieldType": 6, "fieldLabel": "Full name", "fieldName": "fullName", "required": true},
      {"fieldType": 8, "fieldLabel": "Email", "fieldName": "email", "required": true},
      {
        "fieldType": 7,
        "fieldLabel": "Topics",
        "fieldName": "topics",
        "multipleChoice": true,
        "fieldOptions": [
          {"label": "Billing", "value": "billing"},
          {"label": "API", "value": "api"}
        ]
      }
    ]
  }
}
```

A submission produces trigger output like this:

```json
{
  "submittedAt": "2026-11-14T09:30:12.345Z",
  "body": {
    "fullName": "Ada Lovelace",
    "email": "ada@example.com",
    "topics": ["billing", "api"]
  }
}
```

Later steps reference the values as `${trigger_1.body.fullName}`, `${trigger_1.body.email}` and `${trigger_1.body.topics}`.
