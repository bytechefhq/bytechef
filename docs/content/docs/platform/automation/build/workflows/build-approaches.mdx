title: Build Approaches
description: Choose how you build automations in ByteChef - no-code on the visual canvas, low-code with a Script step, or full-code as a Code Workflow - all running on the same engine.
---

ByteChef supports three ways to author an automation: no-code on the visual canvas, low-code with a Script step on the canvas, and full-code as a Code Workflow. All three run on the same workflow engine with the same components and triggers. You can mix them in one project and move a workflow from one approach to another.

## No-code: the visual canvas

Build the workflow in the [workflow editor](/platform/automation/build/workflows/workflows). Add a trigger and actions from the built-in components, map data between steps with [data pills](/platform/automation/build/workflows/data-pills), and add branching and loops with [flow controls](/platform/automation/build/workflows/flow-controls). Most integrations need only an action and its fields.

## Low-code: the canvas plus a Script step

When a step needs logic that no component provides, for example reshaping a payload, computing a value or parsing an unusual format, add the **[Script](/reference/components/script_v1)** component and write the logic in JavaScript or Python. See [Scripting languages](/platform/automation/build/workflows/code-workflows#scripting-languages). The Script step receives data from previous steps and returns a value that later steps use, like any other component. The rest of the workflow stays visual.

## Full-code: a Code Workflow

Define the whole workflow in code as a **[Code Workflow](/platform/automation/build/workflows/code-workflows)** in Java, JavaScript, Python or Ruby, and deploy the artifact through the API. Use this approach when workflows must live in version control, go through code review and ship through CI. A Code Workflow runs on the same engine as a canvas workflow; only authoring and lifecycle differ. Code Workflows require the Enterprise Edition.

To give your own users an authoring UI in your product, see [Custom Components](/platform/settings/components/custom-components) and the [embedded Workflow Builder](/platform/embedded/build/automations/automation-workflows).

## Choose an approach

| Situation | Approach |
|---|---|
| Integrations and standard logic | **No-code** on the canvas |
| One step needs a transformation or glue logic | **Low-code**: canvas plus a [Script](/reference/components/script_v1) step |
| The workflow must be in Git, reviewed and shipped through CI | **Full-code**: a [Code Workflow](/platform/automation/build/workflows/code-workflows) |
| Requirements are not clear yet | Start with **no-code**; add a Script step or move to code later |
