A **Data Stream** is a workflow step for bulk record transfer, for example syncing contacts between CRMs, exporting rows to a warehouse or migrating data between systems. The Data Stream node reads records from a **source**, optionally transforms each record through a **processor**, and writes them to a **destination** as a managed batch job, instead of looping over items one action at a time.

Like the AI Agent, the Data Stream node is a *cluster root*: its source, processor and destination are cluster elements inside the node, not separate workflow steps.

## The slots

| Slot | Role |
|---|---|
| **Source** | Where records are read from: a component operation that streams items (for example, read rows or list records). |
| **Processor** (optional) | Transforms each record in flight. The standard processor is the **Field Mapper**, which maps source fields onto the destination's shape. |
| **Destination** | Where records are written: a component operation that accepts items in bulk. |

## Simple vs Advanced editor

Click the Data Stream node to open the **Data Stream Editor**. It has two modes. Switch to the advanced mode with **Advanced** in the header.

- **Simple editor** (default) - a wizard with four steps: **Source** (select the source component, connection and properties), **Destination** (the same for the destination), **Mapping** (the Field Mapper's field assignments) and **Test** (run the mapping and inspect the output schema). Use **Previous**, **Next** and **Finish** to move through the steps. Each step unlocks when the previous one is configured. On the Mapping step, **Auto-map matching fields** creates assignments for fields whose names match.

- **Advanced editor** - the raw cluster-elements canvas, where source, processor, and destination appear as wired nodes. Use it to configure element parameters directly or to swap the processor for something other than the Field Mapper.

The simple wizard is available only while the processor slot holds the standard **Field Mapper**. If you replace it with a different processor in the advanced editor, the node opens in advanced mode from then on, because the wizard cannot represent another processor.

Both modes edit the same configuration, and your last mode choice is remembered per node.
