A **component** is ByteChef's unit of integration. It bundles the *actions*, *triggers* and *connection*
definition for one external system or capability. A workflow step is one component action, and a workflow
trigger is one component trigger.

| Part | Description |
|---|---|
| **Action** | An operation the workflow performs, such as creating a record, sending a message or reading a file. It takes typed input properties and returns a typed output that later steps can read. |
| **Trigger** | An event that starts a workflow, such as an incoming webhook, a schedule or a change in a polled resource. |
| **Connection** | How the component authenticates. You create a connection once and reuse it in every step that uses that system. |

The [workflow editor](/platform/automation/build/workflows/workflows) offers components in its step picker.
Component actions are also available to [AI agents](/platform/automation/build/workflows/ai/agent) as tools.

## Finding a component

The **[Component Reference](/reference/components)** is generated from the components and lists every
action, trigger and connection property of each component. More than 250 components are available.

The catalog covers these categories:

| Category | Examples |
|---|---|
| **CRM & sales** | Salesforce, HubSpot, Pipedrive, Apollo, ZoomInfo, Active Campaign, Freshsales |
| **Project management** | Jira, Asana, Linear, Notion, ClickUp, Monday, Trello |
| **Communication** | Slack, Microsoft Teams, Discord, Telegram, Twilio, Zoom |
| **Email** | Google Mail, Microsoft Outlook 365, Brevo, Mailchimp, SendGrid, Resend |
| **E-commerce** | Shopify, Stripe, WooCommerce, QuickBooks, Xero |
| **Cloud storage** | Google Drive, Dropbox, Box, Microsoft OneDrive, AWS S3 |
| **Productivity** | Google Docs, Google Sheets, Microsoft Excel, Airtable, Notion |
| **Developer tools** | GitHub, GitLab, Bitbucket, PagerDuty, Jenkins |
| **AI / ML** | OpenAI, Anthropic, Mistral, Gemini, Ollama, Perplexity |
| **Vector stores & memory** | Pinecone, Qdrant, Weaviate, Milvus, pgVector, chat-memory elements |
| **Databases** | MySQL, PostgreSQL, MongoDB, Supabase, Snowflake, Google BigQuery |
| **Helpers** | HTTP Client, GraphQL Client, JSON Helper, XML Helper, Date Helper, Math Helper, JWT Helper, Logger |
| **Files** | CSV, JSON, XML, XLSX, ODS, PDF Helper, File Storage, FTP |
| **Web** | Firecrawl, ZenRows, Browser Use, Brave, Tavily |

[Flow controls](/platform/automation/build/workflows/flow-controls) (Condition, Branch, Loop, Loop
Break, Each, Map, Parallel, Fork/Join, Subflow, Graph, Error Handler, Stop Job) are not components. They
are task dispatchers with their own [reference section](/reference/flow-controls).

## Versions

Every component has a version, stored in the workflow as part of the step type
(`slack/v1/sendChannelMessage`: component `slack`, version `v1`, action `sendChannelMessage`). Most components are on `v1`. Some have a `v2`, for example Google Sheets,
Microsoft Excel and the chat memory components. Because the version is stored per step, a new version
does not change existing workflows: each step keeps running the version it was created with until you
change the step. Select the version at the bottom of the step's properties panel.

## When no component fits

Options, from least to most effort:

1. **A Script step** - JavaScript or Python inside the workflow, for logic used in one place.
   See [Scripting languages](/platform/automation/build/workflows/code-workflows#scripting-languages).
2. **The [HTTP Client](/reference/components/http-client_v1) component** - an HTTP request to any REST
   API, configured in the step.
3. **An [API connector](/platform/settings/components/api-connectors)** - import an OpenAPI
   specification to get a component with one action per endpoint.
4. **A [custom component](/platform/settings/components/custom-components)** - your own code, with its
   own actions, triggers and connection definition.

## Source code

The components are in `server/libs/modules/components/` in the ByteChef repository and are licensed
under Apache 2.0. Each component has a `README.md` next to its source; the Component Reference is
generated from the component definitions and these READMEs.
