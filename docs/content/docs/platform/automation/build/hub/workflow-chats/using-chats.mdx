## Open a workflow chat

{/* TODO screenshot: the Chats page - left sidebar with chat-enabled workflows grouped by project, an open conversation in the main panel, and the Clear messages button in the header */}

1. Click **Chats** in the Automation navigation.
2. In the left sidebar, find the workflow under its project. The sidebar lists every workflow
   with a [hosted chat trigger](/platform/automation/build/hub/workflow-chats/enable-chat) that
   is deployed and enabled in the selected environment.
3. Click the workflow to open its conversation.

When no workflow qualifies, the page shows a **No chat workflows yet** empty state.

  Starting workflow chats and agent chats from the AI Hub composer, with one chat row per conversation, is not available in the latest released version of ByteChef.
</Callout>

## Send a message

Type in the composer and send. ByteChef calls the workflow's
[New Chat Request trigger](/platform/automation/build/hub/workflow-chats/enable-chat) with your
message and the current conversation ID. The workflow runs, and the reply appears in the thread.

While a turn is running, the composer waits for the reply, and the other workflows in the sidebar
are disabled so that you cannot switch away mid-run. When the reply finishes, you can send the
next message.

## Streamed replies

When the workflow contains a step that streams its output, such as an AI Agent, the reply arrives
as a stream:

- **Incremental text** is appended to the reply as it is produced.
- **The final result** replaces or completes the reply when the run ends.

Workflows without a streaming step return the whole reply when the run completes.

## Attachments

Click the attachment button in the composer to add images or text files to a message. They are
delivered to the workflow in the trigger's `attachments` output, where a step can read, parse, or
store them. For example, a step can extract data from an uploaded CSV file.

## Conversation history

Each workflow keeps one conversation while you stay on the **Chats** page. Switching to another
workflow saves the current thread and restores that workflow's thread. Conversations are held in
the browser only: leaving the **Chats** page or reloading it clears them.

To start over, click **Clear messages** in the page header. This resets the active conversation and
starts a new conversation ID. The button is disabled while a turn is running.

## Environments

Workflow chats follow the environment selected in the left sidebar header. The **Chats** page
lists the chat workflows deployed in that environment, and conversations run against that
environment's connections and deployed workflow version. A chat in `DEVELOPMENT` is isolated from
`PRODUCTION`.

<Callout title="Workflow not listed?">
  A workflow appears on the **Chats** page only when its **New Chat Request** trigger is set to
  **Hosted Chat**, the trigger is enabled, and the workflow is deployed and enabled in the selected
  environment. Check the [trigger configuration](/platform/automation/build/hub/workflow-chats/enable-chat) if a workflow is missing.
</Callout>
