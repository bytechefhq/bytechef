The workflow editor's **Playground** panel has a microphone button when the open workflow has a
voice trigger. Use it to speak to the workflow without the chat widget or the AI Hub, for example
while you adjust prompts, models, and turn-taking behavior.

## When the microphone button appears

The button appears when at least one trigger of the open workflow has a **Real-Time Workflow**
(the `websocketTasks` extension that runs during the voice session):

- A workflow with a `browser/v1/voiceSession` trigger shows the button.
- A workflow without a voice trigger does not.
- A new workflow shows the button after you add the trigger and save.

Testing does not require deployment. The editor test path reads the saved draft workflow
definition.

## Editor test path and production

The editor uses a separate WebSocket endpoint:

```
production:   wss://<host>/api/automation/webhooks/{webhookId}/wss
editor test:  wss://<host>/api/platform/internal/workflow-tests/{workflowId}/wss
```

Both endpoints use the same handler. The editor path:

- Requires your ByteChef session cookie, so it cannot be embedded cross-origin.
- Reads the saved draft definition; no deployment is required.
- Mints session tokens with `POST /api/platform/internal/workflow-tests/{workflowId}/voice-session-token`.
- Runs the same audio bridge and task chain as production.

## Run a test session

1. Click the microphone icon in the **Playground** header. The icon changes to a red microphone-off icon while active.
2. Grant microphone permission when the browser prompts.
3. Wait until the status banner changes from **Connecting microphone…** to **Listening… click mic to end.** While the assistant responds, it shows **Assistant is speaking…**.
4. Speak. Transcripts and assistant responses appear in the chat thread.
5. Click the microphone-off icon to end the session.

## Iterate on a prompt or model

1. Change the system prompt or LLM model in the Deepgram Voice Agent task.
2. Save the workflow.
3. Start a test session and listen to the result.

Each session starts fresh: the previous Deepgram WebSocket closes, a new sub-workflow job starts,
and chat memory resets. To keep conversation memory across sessions, set a stable `threadId` on
the agent task. For example, `${callSid}` is unique per session, and a constant such as
`'editor-test'` is shared by all editor sessions.

## Costs and limits

Editor sessions use real Deepgram minutes and are billed by Deepgram. The 30-minute session limit
also applies in the editor. End sessions with the microphone-off icon when you are done.

## Browser requirements

Chrome 66+, Firefox 76+, or Safari 14.1+. On unsupported browsers, the button is disabled and its
tooltip explains why.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| The microphone button does not appear | The workflow has no voice trigger. Add a `browser/v1/voiceSession` trigger with a Real-Time Workflow. See the [Voice Quickstart](/platform/automation/build/voice/quickstart). |
| The microphone button is disabled | The browser is unsupported (see the tooltip), or the workflow has not been saved yet. |
| "Workflow has no websocketTasks defined on its trigger" | The trigger has no Real-Time Workflow. Open the trigger and add the sub-workflow under **Real-Time Workflow**. |
| Audio works but there is no response | The trigger's sample rate (16000 by default) differs from the Voice Agent's `audioInputSampleRate`. The output rate (`audioOutputSampleRate`, typically 24000) is independent. |
| Permission denied, or the button does nothing | The browser stored a denial for the origin. Reset it (Chrome: `chrome://settings/content/microphone`; Firefox: **Settings > Privacy & Security > Permissions > Microphone**; Safari: **Settings > Websites > Microphone**) and reload. |
| The session closes after 30 minutes | The server limits each session to 30 minutes. Start a new session. |
