title: "Tool Invocations"
description: "A log of the tools AI clients called through your MCP servers and the management MCP server - which tool ran, how it ended, and how long it took."
---

When an AI client calls a tool on one of your [MCP servers](/platform/automation/deploy/mcp-servers)
or on the [management MCP server](/platform/settings/mcp-server), ByteChef records the call. **Tool Invocations** lists those records, so you can see which tools are
being used, which ones fail, and how long they take. Open it from **Tool Invocations** in the left
sidebar, next to **Workflow Executions**.

The page is available on Enterprise Edition only.

<Callout type="info">
    A record holds the identity and outcome of a call only: which tool ran, through which MCP server,
    how it ended, and how long it took. The tool's input parameters and its output are never stored.
</Callout>

---

## What is recorded

A record is written for every tool call an AI client makes through an MCP server in the workspace:

- **Component tools** - a component action exposed as a tool, such as Slack's **Send Message**.
- **Workflow tools** - a project workflow exposed as a tool.

The call is recorded whether it succeeds or fails. A call to a tool or a server that is turned off is
rejected before it runs and is not recorded.

Calls to the [management MCP server](/platform/settings/mcp-server), such as `listProjects` or
`buildWorkflow`, are recorded too. A management call is listed under the workspace it worked in: the
`workspaceId` it was given, or your only workspace when you belong to just one. It is listed under the
environment it was given, or under Development when it named none. A call that named no workspace
while you belong to several is recorded but appears on no page. A management tool that answers with
an error is recorded as `ERROR`.

The page lists automation calls only. Calls made through an embedded integration are recorded
separately and appear on the embedded [Tool Invocations](/platform/embedded/monitor/tool-invocations)
page.

Tool calls an AI Agent makes while a workflow runs are not recorded here either. They appear in the
run's execution view, in the agent's call list, together with any approval a reviewer gave or refused.

## The invocations table

Each call is one row, newest first:

| Column | What it shows |
|---|---|
| **Tool** | The tool name the AI client called. |
| **Surface** | Where the call came in: **Automation MCP** for one of your MCP servers, **Management MCP** for the management MCP server. |
| **Component** | The component and the operation a component tool ran, such as `slack / sendMessage`. Workflow tools show a dash. |
| **Outcome** | How the call ended, for example `SUCCESS`, `ERROR` or `TIMEOUT`. |
| **Duration** | How long the call took, in milliseconds. |
| **Date** | When the call was made. |

The list shows 50 rows per page. Use the **Refresh** button in the page header to load the latest
calls.

### How a workflow tool call ends

A workflow tool starts a workflow run and waits for it. The outcome reflects where the run was when
the call returned:

| Outcome | The workflow run |
|---|---|
| `SUCCESS` | Completed, and the call returned its output. |
| `ERROR` | Failed, could not start, or was stopped before it finished. |
| `TIMEOUT` | Was still running when the call stopped waiting for it. |
| `APPROVAL_REQUIRED` | Paused at an approval step and waits for a person to decide. |
| `SUSPENDED` | Paused at a step such as a delay and continues on its own later. |

## Filter invocations

| Filter | Narrows the list to |
|---|---|
| **Surface** | Calls that came in through one surface. |
| **Outcome** | Calls that ended one way: Success, Error, Connection required, Timeout, Approval required, Approval denied or Suspended. |
| **MCP Server** | Calls made through one MCP server. The filter appears when the workspace has at least one MCP server. Management MCP calls belong to no MCP server, so choosing one hides them. |
| **Start date** / **End date** | Calls made within a date range. |

---

## Scope

The list is scoped to the current workspace and the current
[environment](/platform/automation/deploy/environments). Switching either one in the left sidebar
reloads the list and clears the filters. A call made through an MCP server in Production does not
appear while you are looking at Development.

---

## Who can see it

Organization admins see every workspace's invocations. Other users see a workspace's invocations when
their [workspace role](/platform/automation/settings/users) lets them view workflows, which the
built-in Viewer, Editor and Admin roles all do. Connected users of an embedded integration cannot read
the log.

---

## Retention

Records are deleted after 90 days. A cleanup job runs once a day, at 02:30 server time. In a
multi-tenant installation it cleans up every tenant's records, and one tenant's failure does not stop
the others.

| Property | Purpose |
|---|---|
| `bytechef.tool-invocation-log.retention-days` | How many days a record is kept. Defaults to `90`. |
